# `oknx serve` operations

Generated by `oknx --lang en serve describe --markdown` from the descriptions in `oknx/src/serve/Ops.h`, the
same source the MCP tools, the API routes and the input check come from. `*` marks a required argument.
Every operation on an interface also takes `port` (default 3671).

### `discover` — Search for KNXnet/IP interfaces

Multicast SEARCH and mDNS on the local network; lists every interface that answers.

Class: `net` · in the leader · time limit: 8 s

| Argument | type / range | meaning |
|---|---|---|
| `timeout_ms` | integer 500..5000 | how long to listen |

### `device_state` — Interface state from its firmware

Class: `group-monitor` · in the leader · time limit: 330 s · reports progress

| Argument | type / range | meaning |
|---|---|---|

### `setpa` — Give a device its individual address

As `oknx setpa`: with serial, A_IndividualAddressSerialNumber_Write to that device; without, the one device in programming mode (waits up to wait_s for exactly one). Checks the address is free, reads it back, restarts the device so it keeps it (restart:false leaves that out on the serial-number way; in programming mode the restart is what ends it and is always sent). Several devices in programming mode: BUSY with their serial numbers. Changes the device.

Class: `bus-write` · in the worker · time limit: 180 s · reports progress

| Argument | type / range | meaning |
|---|---|---|
| `ip` * | string (ipv4) | IPv4 address of the KNXnet/IP interface |
| `pa` * | string (knx-pa) | the new individual address |
| `port` | integer 1..65535 | KNXnet/IP port of the interface (default 3671) |
| `restart` | boolean | restart afterwards so the device keeps the address (default true; serial-number way only) |
| `serial` | string | serial number of the device, e.g. 00FA:01A2B3C4 |
| `wait_s` | integer 0..120 | how long to wait for exactly one device in programming mode |

### `ftc_login` — Sign in to a password-protected FTC device

The FTC challenge-response, as `oknx <pa> login`. The password never travels over MCP or the API: serve takes it from OKNX_FTC_PW_<a>_<l>_<d> of its own environment, or asks in its own terminal. Opens the device's write window until it goes idle.

Class: `bus-write` · in the worker · time limit: 150 s · reports progress

| Argument | type / range | meaning |
|---|---|---|
| `ip` * | string (ipv4) | IPv4 address of the KNXnet/IP interface |
| `pa` * | string (knx-pa) | individual address of the device |
| `port` | integer 1..65535 | KNXnet/IP port of the interface (default 3671) |

### `ftc_send` — Upload a file to a device (FTC)

As `oknx <pa> send <src> <dst> [safe|fast]`; src is a file on the machine serve runs on. A transfer stopped by a crash leaves the file open on the device for up to 30 s (no heartbeat), a new one is refused (0x41) until then. Changes the device.

Class: `bus-write` · in the worker · time limit: 3600 s · reports progress

| Argument | type / range | meaning |
|---|---|---|
| `dst` * | string | path on the device, optionally sd/ or efc/ (no spaces) |
| `ip` * | string (ipv4) | IPv4 address of the KNXnet/IP interface |
| `mode` | string ["safe","fast"] |  |
| `pa` * | string (knx-pa) | individual address of the device |
| `port` | integer 1..65535 | KNXnet/IP port of the interface (default 3671) |
| `src` * | string | local file path (no spaces) |

Run-Tests.ps1 -TestProfile <profile> next to the bench config. The run holds the bench through its lock file; follow it with bench_state. Needs "suite_run": true in a bench site of the rules. Changes the bench devices.

Class: `bus-write` · in the leader · time limit: 15 s

|---|---|---|
| `profile` * | string | profile name from scripts/Test/Profiles, e.g. quick-check |
